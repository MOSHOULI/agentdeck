# CLI 同步的只读计划

此功能属于开发中的源码，尚未随正式安装包发布。

```sh
cargo run --locked -p aisync-cli -- sync --tools codex,claude-code --dry-run
```

`--dry-run` 为明确选择的 Agent 输出 JSON 元数据计划。不会运行 Agent、npm、Git 或安装器，不会创建 profile、备份、密钥库或记忆数据库，也不读取配置、模板或记忆内容。它会读取目录元数据。`--yes` 与 `--dry-run` 互斥，避免预览意外变成应用请求。

报告列出已声明适配器对应的指令管理块目标和本地记忆导出目标。含 `~` 的路径是符号路径，不会展开或访问。模板名称不是简单名称时，不猜测源路径，而是留空并给出警告。记忆别名与非法目标复用导出适配器的纯校验逻辑。本地记忆文件的存在不证明外部 Agent 会使用它。

## 如何理解结果

- `batchStatus: unverified`：已生成声明式计划，**不代表**安装资格已验证，也不是应用许可。
- `batchStatus: unsupported`：至少一个目标没有支持的操作，或记忆导出目标无效。仍以 0 退出，便于调用方检查报告。
- `notChecked` 明确列出尚未检查的安装资格、文件内容、路径安全和权限、实际差异、记忆条目及备份可用性。没有“已就绪”状态。
- 未知 ID 或目录读取错误会非零退出，不输出半份 JSON。参数错误以 2 退出；报告或输出失败也非零退出。
- 这不是文件 diff，也不是与快照绑定的授权令牌。目录元数据变化后，再次运行可能产生不同计划。不展示模板内容、凭据或记忆文本。

实际执行 `sync --yes` 仍使用现有校验与备份流程，可能初始化缺失的模板和记忆库，也可能失败或部分完成。只读计划不会改变这些语义，不会让批量同步变成事务。模型设置、MCP 服务器、技能和软件安装不属于 CLI `sync`。桌面 MCP 预览是另一项带过期检查的功能。

## 只读目录处理

全新的用户目录可以直接使用内置目录，不创建 `.agentdeck`。如果协调锁已存在，只读打开并获取共享锁；锁繁忙或不安全、已有运行时目录却没有锁、存在恢复日志时，都会拒绝。不会新建锁，也不会恢复中断的目录更新。正常应用恢复仍是独立操作，不要删除锁或恢复日志来强行预览。

持有锁时，目录选择与正常读取策略相同，包括严格识别的官方 v1 目录迁移。结果仍只是读取时的元数据，不保证随后应用时的目标状态。

## 验证与限制

测试在隔离临时用户目录中执行真实 CLI 二进制，比较前后文件及目录，放置合成 PATH 可执行程序和合成配置/记忆秘密，并覆盖非法选择、冲突参数、不支持的目标、运行时元数据、缺失/繁忙锁及待恢复更新。纯逻辑测试覆盖记忆别名校验和模板源路径留空。这些都是合成测试，不是实际 Agent 安装、Windows GUI、真实 profile 应用或在线 MCP 验收。
