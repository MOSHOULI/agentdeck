# AgentDeck 1.1.0

[English](RELEASE-1.1.0.md) | 简体中文

这是 1.1.0 的历史发布说明，不描述当前开发分支。后续的安装来源检查、受限 npm
安装计划和 DSH 盘点见 [安装证据](INSTALLATION-EVIDENCE.zh-CN.md) 与
[DSH 被动盘点](DSH-PASSIVE-INVENTORY.zh-CN.md)，不计入本次历史版本的发布范围。
仅凭版本字符串不能确定构建使用的源码。

本版本强化并补全已有 Windows 桌面工作流，不替换 React/Tauri/Rust 架构。

## 变更

- 备份恢复保留密钥并验证数据真实性；支持可迁移路径、已删除文件恢复、随机备份 nonce 和旧格式兼容。
- 配置原子写入与回滚、保留用户指令区块、有界安装器，以及如实呈现的能力和警告状态。
- 事务式签名注册表更新、运行时注册表加载，以及已安装版本持久化。
- 可撤销的记忆导出、明确的手动选择、需主动开启的自动采集（默认关闭）、取消和部分错误反馈。
- 仅针对受管理服务器的原子 MCP 同步、可用的 CLI 命令，以及显式开启的只读浏览器演示。
- 锁定的依赖、隔离 HOME 测试运行器、Windows 原生测试和可复现的 NSIS 构建产物。
- 软件安装与可选的 profile 配置分离。探测失败仍为错误，不被视为未安装；过期的列表数据阻止后续修改。安装来源未经验证时，UI 和核心均禁止自动卸载。

## 验证下载

发布门禁通过后，请从明确指定的 [AgentDeck v1.1.0 发布页](https://github.com/MOSHOULI/agentdeck/releases/tag/v1.1.0)下载安装包。页面不存在表示该安装包尚未发布。

`SHA256SUMS.txt` 标识安装包字节内容，`BUILD_COMMIT.txt` 标识发布构建使用的确切源码修订版本。请将两者与发布提交对应的成功 CI 运行结果进行核对。

CI 会先上传草稿 Release，再次下载其资产，并在公开发布前验证安装包字节、校验和、构建提交和实际 Git 标签提交。已有 Release（包括草稿）或指向其他提交的标签会阻止发布，交由人工核查；不会覆盖已有资产。上传或验证失败可能留下未公开的草稿，重试前必须先检查。

**Windows 安装包未做 Authenticode 代码签名。** 校验和是完整性证据，不是发布者证书验证。

## 安装包与注册表发布渠道

仅含安装包的本次发布使用 `--latest=false`。应用的注册表更新检查使用 GitHub 的 `latest` 下载入口，该入口必须继续提供现有的已签名注册表 manifest 和签名。桌面安装包请使用上方明确的 v1.1.0 链接；Latest 标签标识的是保留的注册表更新源，不是最新的桌面二进制。本次不包含新的已签名注册表更新，因为原始签名私钥不可用。签名和下载失败仍会报错，已有信任锚保持不变。

升级时，仅当保留的两份运行时注册表文件与原始已签名 v1.0.0 资产的 SHA256 指纹完全一致，且版本标记不存在或为 `1.0.0`，应用才会使用改进后的内置注册表。这个过程只改变所选来源，不删除或重写原文件及其版本标记。自定义、来源未知和较新的运行时注册表继续使用。签名更新必须同时高于当前实际使用的注册表版本和内置版本，避免旧更新源重新引入已被替代的元数据。无效的版本元数据、不完整的带版本安装，以及恢复失败，仍会报错。

## 范围与已知限制

- Windows 10/11 x64 是完整桌面的目标平台。备份需要 Git；npm 类型 Agent 需要 Node.js/npm。
- 尚无安装来源台账，新安装也不例外。因此，自动卸载保持关闭，直至能够验证来源。Agent 软件升级尚未实现。PATH 中找不到可执行文件，并不能证明机器其他位置没有安装。
- 应用 profile 是需要单独确认的操作，但尚未实现配置差异预览和三方冲突对账。已有回滚不能防范所有并发外部编辑。
- Linux 核心/CLI 测试不能证明 Linux 桌面可用，也不能证明非 Windows 平台具有安全密钥库。
- 自动化 Windows 测试和打包不等于人工原生 GUI 验收，也不代表测试过每一种第三方安装器、网络或登录流程。
- 真实环境集成测试有意保持忽略；常规 CI 不使用真实账户密钥或个人对话。
- 记忆导出为本地 Markdown；外部 Agent 需要明确接入上下文或配置。技能分发明确不受支持。
- 本地记忆数据库和写入前的配置恢复副本可能含有明文。Git 快照会加密配置副本；DPAPI vault 密钥绑定用户/机器。
- 旧备份历史保留原有的确定性密文。多文件回滚不是断电恢复日志。
- CI 中没有原始注册表签名私钥。不生成替代密钥，不声称提供新的已签名注册表更新源，并保留已有信任锚。桌面二进制升级通过安装包分发。

依赖审计、修复情况和剩余仅影响 Linux 的上游发现，记录于 [DEPENDENCY-SECURITY.md](DEPENDENCY-SECURITY.md)。
